BLOCKER: [SocketServer.scala](/home/florent/kafka-current-london-2026/.claude/worktrees/io-uring/core/src/main/scala/kafka/network/SocketServer.scala:957)

Exact problem: the io_uring path builds `new InetSocketAddress(endPoint.host, endPoint.port)` directly. Kafka stores wildcard listener hosts from configs like `PLAINTEXT://:9092` as `null` (`SocketServerConfigs.listenerListToEndPoints`), while the NIO path explicitly maps blank/null hosts to `new InetSocketAddress(port)`.

Failure scenario: with the default `socket.selector.implementation=auto` on Linux + PLAINTEXT, a normal wildcard listener `PLAINTEXT://:9092` resolves to io_uring and the Processor construction throws `IllegalArgumentException: hostname can't be null` before the broker can start. If a blank string ever reaches this path, Java binds it to localhost rather than wildcard, also diverging from NIO.

Suggested fix: mirror `Acceptor.openServerSocket`:

```scala
val bindAddress =
  if (Utils.isBlank(endPoint.host)) new java.net.InetSocketAddress(endPoint.port)
  else new java.net.InetSocketAddress(endPoint.host, endPoint.port)
```

Add a regression test covering io_uring bundle construction or bind-address derivation for `PLAINTEXT://:9092`.
